# Шифрование бэкапов (age)

**Принцип:** у GitHub есть только **публичный** ключ (`age1…`). Им можно зашифровать, но нельзя расшифровать.
Расшифровать может только владелец **приватного** ключа (`AGE-SECRET-KEY-1…`).
Даже при взломе GitHub или папки на Google Drive бэкапы прочитать нельзя.

> ⚠ **Потеря приватного ключа = потеря всех зашифрованных бэкапов.** Восстановить его невозможно,
> «сбросить» тоже. Поэтому ключ хранится минимум в двух независимых местах **до** включения шифрования.

## 1. Установить age (Windows)
https://github.com/FiloSottile/age/releases → `age-vX.Y.Z-windows-amd64.zip` → распаковать,
например, в `C:\Tools\age\` (там `age.exe` и `age-keygen.exe`).

## 2. Сгенерировать ключ (один раз, на своём компьютере)
```
C:\Tools\age\age-keygen.exe -o fm-backup-key.txt
```
На экран выведется `Public key: age1…` — это **публичный** ключ, его можно показывать.
Файл `fm-backup-key.txt` содержит **приватный** ключ.

## 3. Где хранить приватный ключ (минимум два места)
1. **Менеджер паролей** (Bitwarden, 1Password, KeePass) — защищённая заметка «FavoriteMotors backup key»
   с полным содержимым файла.
2. **Бумага** — распечатать строку `AGE-SECRET-KEY-1…` и положить дома в надёжное место,
   отдельно от компьютера. Можно добавить USB-флешку там же.

Нельзя: в Google Drive рядом с бэкапами, в GitHub, в мессенджеры, в почту, в чат с Claude/GPT.
После переноса в хранилища удалите `fm-backup-key.txt` с рабочего стола
или держите в папке, которая не синхронизируется в облако.

## 4. Пробное шифрование и расшифровка (ДО включения)
```
echo проверка > test.txt
C:\Tools\age\age.exe -r age1ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ -o test.txt.age test.txt
C:\Tools\age\age.exe -d -i fm-backup-key.txt test.txt.age
```
Должно вывести `проверка`. Затем проверить, что ключ из **менеджера паролей** тоже работает:
вставить его в новый файл `key-check.txt` и повторить расшифровку с ним.

## 5. Включение для JSON-бэкапа (GitHub Actions)
1. GitHub → репозиторий → Settings → Secrets and variables → Actions → **Secrets** → New:
   `AGE_RECIPIENT` = `age1…` (публичный ключ).
2. Там же → **Variables** → New: `BACKUP_ENCRYPT` = `1`.
3. Actions → **Backup to Google Drive** → Run workflow. В логе: `шифрование: да`.
4. Скачать новый `.json.age` из Drive → расшифровать → самопроверка:
   ```
   age -d -i fm-backup-key.txt favoritemotors-backup-ДАТА.json.age > backup.json
   cd backup && node restore-json.mjs ..\backup.json --out restore-check
   ```
   Ожидается `Самопроверка файла: manifest совпал`.
5. **Если шаг 4 не прошёл — сразу удалить переменную `BACKUP_ENCRYPT`** (бэкапы снова пойдут открытыми, без потерь).

pg_dump-слой шифруется **всегда** (незашифрованный дамп workflow не загружает) — см. `docs/PG_DUMP_SETUP.md`.

## 6. Старые незашифрованные бэкапы
В папке Drive уже лежат открытые JSON-файлы с паспортными данными. Рекомендация:
проверить, что папка **не расшарена** никому (Drive → папка → Поделиться). Удалять старые файлы —
только после того, как зашифрованная цепочка проработает 1–2 недели и пройдёт пробное восстановление.
Это ваше решение, автоматически ничего не удаляется.

## 7. Если пропал рабочий компьютер
1. На любом компьютере установить age (шаг 1), Node.js 22, PostgreSQL client.
2. Достать приватный ключ из менеджера паролей (или перепечатать с бумаги) в файл `fm-backup-key.txt`.
3. Скачать с Drive последние `*.dump.age` и `*.json.age`, клонировать репозиторий с GitHub.
4. Дальше — `RESTORE.md` с шага 1.
Доступ к Google-аккаунту (Drive) и GitHub защитите двухфакторной аутентификацией с резервными кодами,
которые хранятся там же, где бумажный ключ.

## 8. Ручная кнопка «Скачать бэкап» в CRM
Сейчас она скачивает **открытый** JSON (только администратор, с предупреждением).
Безопасный вариант на будущее (не реализован, отдельное согласование): шифровать в браузере тем же
публичным ключом (библиотека `age-encryption` работает и в браузере). Публичный ключ можно хранить
в коде — он не секретный. Тогда кнопка будет скачивать `.json.age`, который откроется только вашим ключом.
